# Wi‑Fi 7 / MLO Lab для Xiaomi BE7000

## Цель

Я хочу вернуть в NETSCOPE заводскую топологию Xiaomi BE7000: 2,4 ГГц плюс два
5‑ГГц PHY, где 5G low и 5G high образуют один MLD для совместимого клиента.
Целевая конфигурация лаборатории — 160 МГц на нижнем 5 ГГц и 80 МГц на верхнем
5 ГГц. Это Wi‑Fi 7 за счёт EHT/MLO, а не один канал 320 МГц и не 6 ГГц.

## Что известно из заводской прошивки

Публичный профиль содержит только управляющие константы без firmware blobs и
caldata конкретного устройства.

| Режим | GPIO 453 | GPIO 454 | ART offset | CNSS BDF | MLO |
|---|---:|---:|---:|---:|---:|
| Split, три PHY | 1 | 0 | `0x33000` | `0x1008` | включён, mask 2 |
| Single, baseline | 0 | 1 | `0x65000` | `0x2` | выключен |

Оба окна калибровки имеют длину 184 320 байт. Заводская логика не ограничена
переключателем LuCI: она останавливает зависимые процессы, меняет аппаратный
split state, подаёт согласованные параметры CNSS/BDF/caldata, создаёт MLO
topology и затем перезапускает систему. Копирование одной строки UCI эту
последовательность не воспроизводит.

## Почему MLO сейчас не включено

В QWRT присутствуют EHT/MLO участки hostapd/QCA wrapper, однако текущая
загрузка поднимает внешний QCN9224 в single-PHY режиме. Пока нет третьего PHY,
создание второго link VAP или одинакового SSID не превращает систему в MLD.

Дополнительные риски:

- порядок инициализации QCA radio влияет на PHY numbering и состояние RF;
- BDF должен соответствовать режиму и конкретной плате;
- GPIO участвуют в аппаратном split, а их электрическое поведение под QWRT ещё
  не измерено;
- unload/reload CNSS может зависнуть или вызвать kernel panic;
- Ethernet не является out-of-band каналом и исчезнет вместе с зависшим
  ядром;
- MLO association нельзя доказать только наличием EHT beacon или одинакового
  SSID.

## Что реально означает «без UART»

Без UART можно сделать эксперимент, который **не должен пережить холодное
включение**. Это уменьшает риск постоянного brick, но не даёт полной
наблюдаемости и не исключает локальный power cycle.

Разрешённый класс будущего эксперимента:

1. Роутер полностью загружается в известный single-PHY baseline.
2. LAN по кабелю и локальный доступ к питанию проверены до старта.
3. Candidate state создаётся только в `/tmp`/RAM.
4. Не меняются UCI, overlay boot files, init scripts, bootenv, MTD, ART, MIBIB
   и постоянные ссылки на BDF/caldata.
5. Watchdog запускается до остановки Wi‑Fi/CNSS и требует отдельного
   подтверждения после всех health checks.
6. Любой обычный отказ вызывает возврат runtime snapshot.
7. Kernel hang не маскируется как автоматический rollback: нужен холодный
   power cycle, после которого неизменённая загрузка обязана вернуть baseline.
8. Успешный trial всё равно не устанавливается в автозагрузку.

Если для включения split выяснится, что QWRT читает нужный параметр только из
bootargs или постоянного overlay до загрузки модуля, такой путь не относится к
безопасному no-UART trial и блокируется.

## Матрица тестов

Модель `no_uart_scenarios()` проверяет следующие пути:

| Сценарий | Ожидаемый результат |
|---|---|
| driver init / третий PHY / MLD не поднялись | watchdog возвращает baseline |
| не прошёл LAN или WAN health check | watchdog возвращает baseline |
| оператор не подтвердил результат | timeout возвращает baseline |
| питание пропало до подтверждения | cold boot загружает baseline |
| kernel hang | отмечается необходимость ручного power cycle |
| попытка UCI commit/autostart/bootenv/ART/постоянной записи | блокировка до мутации |
| нет проверенного кабеля или доступа к питанию | блокировка до мутации |
| не совпали fingerprints baseline/vendor tuple | блокировка до мутации |

Даже «успешный» сценарий имеет результат `trial-active-not-committed` и поле
`live_apply_allowed=false`. Тестовый пакет OpenWrt предоставляет только
`status`, `preflight` и `render`; команды `apply/enable/commit` отсутствуют.

## Health checks будущего аппаратного trial

Проверка должна быть последовательной и останавливаться на первой ошибке:

1. Совпали model, board name, версии модулей и fingerprints исходных файлов.
2. Baseline LAN отвечает с отдельного проводного клиента.
3. После runtime split появились ровно три ожидаемых PHY без cal/BDF errors.
4. Исходный management path остался доступен.
5. Оба 5‑ГГц AP поднялись на разрешённых каналах и нужной ширине.
6. MLD сообщает два link ID и согласованные MAC/SSID/security параметры.
7. Wi‑Fi 7 клиент действительно установил multi-link association.
8. Есть двусторонний трафик по обоим линкам, а не только beacon capability.
9. Проходят WAN, DNS, LAN и десятиминутный soak без firmware recovery/crash.
10. Отдельный принудительный fail test возвращает single-PHY baseline.
11. Холодное включение без candidate файлов гарантированно возвращает baseline.

## IoT и MLO

Голосовая колонка и пылесос остаются в отдельной 2,4‑ГГц сети. Она появилась
после периодических сообщений колонки об отсутствии интернета в общей сети.
Пока причина не доказана логами, я рассматриваю band steering/MLO только как
одну из гипотез. IoT-сегмент служит стабильной контрольной группой и не должен
меняться во время MLO trial. Подробности — в [IOT-NETWORK.md](IOT-NETWORK.md).

## Критерий killer feature

Функцию можно назвать готовой только если пользователь видит в NETSCOPE:

- detected PHY topology и точную причину блокировки;
- read-only preflight без обещания включить несовместимое железо;
- одноразовый supervised trial с countdown и явным подтверждением;
- health checks каждого link и доказательство multi-link association;
- автоматический software rollback и честный отдельный статус kernel-hang;
- гарантированный cold-boot baseline без сохранения candidate;
- экспорт обезличенного диагностического bundle.

До прохождения аппаратных gates интерфейс должен показывать `Lab / unavailable`,
а не рабочий переключатель Wi‑Fi 7.

## Что нельзя делать

- записывать ART/caldata или использовать данные другого роутера;
- менять MIBIB, U‑Boot env, boot slot или bootargs ради первого теста;
- добавлять эксперимент в init.d/procd autostart;
- перезапускать всё сетевое дерево вместо изолированного runtime trial;
- считать одинаковый SSID доказательством MLO;
- обещать восстановление watchdog при зависшем ядре.
