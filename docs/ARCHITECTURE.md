# Архитектура NETSCOPE

## Назначение

NETSCOPE — продуктовый слой над QWRT для Xiaomi BE7000. Он не подменяет
ядро/QSDK и не выдаёт бинарную базу QWRT за собственную разработку. Моя часть
проекта отвечает за интерфейс, наблюдаемость, безопасные сетевые операции,
диагностику и воспроизводимые release gates.

```text
Xiaomi BE7000 hardware
        ↓
QWRT / QSDK base
        ↓
NETSCOPE product layer
  ├─ UI and navigation
  ├─ Traffic / Packet Lab
  ├─ VPN Quick setup
  ├─ IoT diagnostics
  ├─ Recovery contracts
  └─ Wi-Fi 7 / MLO Lab
```

## Слои

### 1. Базовая система

QWRT предоставляет kernel, QSDK-драйверы, аппаратную поддержку платы,
network/firewall, LuCI и системные сервисы. NETSCOPE показывает точную версию
базы в интерфейсе и не переименовывает её компоненты в собственные.

### 2. Продуктовый интерфейс

NETSCOPE UI объединяет штатные страницы LuCI и собственные приложения в одной
английской оболочке. Старые страницы QWRT остаются достижимыми: новый дизайн
не должен скрывать аварийные или редкие настройки.

### 3. Наблюдаемость

NETSCOPE Traffic использует conntrack и системные счётчики для списка активных
соединений. Packet Lab управляет ограниченными PCAP-сессиями на USB. Пассивное
наблюдение не расшифровывает TLS и не обещает увидеть пакеты, которые обошли
CPU из-за аппаратного offload.

Захват по умолчанию выключен. Сессия имеет явные start/stop, лимиты, ротацию,
проверку свободного места и fail-safe очистку временных firewall-правил.

### 4. Управляемые сетевые операции

VPN Quick setup разделяет подготовку и применение:

1. Пользователь вводит параметры в локальной вебке.
2. Backend валидирует формат, конфликты портов и пересечения подсетей.
3. Создаётся приватный draft с правами `0700/0600`.
4. Preflight выполняется повторно непосредственно перед активацией.
5. Поддерживаемый runtime получает собственный интерфейс и собственные rules.
6. Watchdog снимает только изменения этого runtime, если нет подтверждения.

Plain WireGuard имеет отдельный экспериментальный runtime. AWG, VLESS/Xray и
Mieru пока остаются prepare-only. Они не должны обозначаться в UI как активные
до появления независимого rollback и интеграционных тестов.

### 5. Лабораторные функции

Wi‑Fi 7/MLO намеренно изолирован от обычных настроек Wi‑Fi. Публичный helper
может выполнить только `status`, `preflight` и `render`. Он не содержит live
activation, autostart и записи постоянного состояния.

## Компоненты и владельцы состояния

| Компонент | Публичный исходник | Изменяемое состояние | Безопасное состояние |
|---|---|---|---|
| VPN Quick setup | `firmware/packages/luci-app-netscope-setup` | приватные drafts и отдельный WG runtime | интерфейс выключен, собственные rules удалены |
| Wi‑Fi 7 Lab helper | `firmware/packages/netscope-wifi7-lab` | только render-файл в `/tmp` | никаких изменений радио |
| Offline safety models | `src/netscope_firmware` | не выполняют I/O | детерминированный JSON-отчёт |
| IoT monitor | `tools/netscope-iot-monitor` | кольцевые журналы на USB | процесс остановлен, сеть не изменена |
| VPN examples | `examples` | ничего без ручной адаптации | документационные заглушки |

## Хранилища

- `/tmp/netscope-*` — только временное runtime-состояние.
- `/mnt/sda1/NETSCOPE/` — приватные drafts, журналы и будущие PCAP-сессии.
- `/etc/netscope/` — только несекретная конфигурация пакетов после появления
  воспроизводимого образа.
- Git — исходники, документация и обезличенные примеры без живых ключей.

Внутренняя NAND не используется как бесконечное хранилище журналов или PCAP.
Отключение USB не должно ломать WAN, DNS, firewall или доступ к LuCI.

## Контракты безопасности

- Новая функция по умолчанию выключена.
- `prepare` не означает `activate`.
- Каждый runtime изменяет только собственный именованный scope.
- Удаление и rollback выполняются сначала для firewall redirects/rules, затем
  для процесса и интерфейса.
- Нет скрытого изменения default route.
- Секреты не возвращаются повторно через публичный API после создания.
- MLO не входит в boot path, пока не доказан аппаратный recovery.
- Kernel hang никогда не обозначается как успешный software rollback.

## Что ещё не опубликовано

Рабочая тема NETSCOPE UI и полный NETSCOPE Traffic пока находятся на тестовом
роутере и должны быть перенесены в отдельные воспроизводимые LuCI-пакеты. Пока
эти исходники не появились здесь и не проходят CI, скриншоты интерфейса не
считаются firmware release.
