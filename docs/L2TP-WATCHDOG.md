# L2TP watchdog NETSCOPE

`netscope-l2tp-watchdog` — отдельный opt-in сервис для уже существующего
офисного L2TP. Он не создаёт учётные данные и не публикует адреса офиса.

## Что проверяется

- наличие ожидаемого PPP-интерфейса;
- маршрут к приватному probe через этот PPP;
- наличие каждого обязательного офисного префикса через тот же интерфейс;
- MTU 1400;
- собственный `NS_L2TP_MSS` с MSS 1360 только для TCP SYN, уходящих в PPP.

После трёх последовательных ошибок сервис вызывает один заранее разрешённый
reconnect-helper и выдерживает cooldown. Он не вызывает `network restart`,
`firewall restart`, не очищает чужие таблицы и при остановке удаляет только
собственный MSS-chain. Сам L2TP при выключении watchdog остаётся как есть.

## Приватная конфигурация

Файл `/mnt/sda1/NETSCOPE/config/l2tp-watchdog.conf` создаётся только на роутере
с правами 0600. Публичный пример намеренно не содержит реальных сетей:

```ini
enabled=1
interface=ppp0
probe=192.0.2.10
routes=192.0.2.0/24 198.51.100.0/24
reconnect=/usr/libexec/netscope-l2tp-reconnect
mtu=1400
mss=1360
```

Значения валидируются как данные, файл не исполняется через `source`/`eval`.
Reconnect path ограничен именованным helper, а не произвольной shell-командой.
Init-сервис в публичном overlay не включён: его разрешают только после создания
и проверки приватной конфигурации.

Состояние видно в VPN Quick setup. Кольцевой журнал событий хранится на USB в
`/mnt/sda1/NETSCOPE/runtime/l2tp/` и не содержит паролей или полного конфига.
