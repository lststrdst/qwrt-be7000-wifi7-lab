# Аудит LuCI NETSCOPE

NETSCOPE сохраняет штатные контроллеры и формы QWRT, но строит над ними свою
навигацию. Поэтому проверяются отдельно дерево LuCI и наши DOM-элементы.

## Зафиксированный baseline QWRT R26.2.2

На Xiaomi BE7000 проверено 6 сентября 2026 года:

- 213 узлов в дереве LuCI;
- 0 отсутствующих CBI-моделей и template views;
- 0 одинаково подписанных соседних пунктов;
- 86 исходных английских названий, для которых тема содержит явное русское
  отображение (названия протоколов и NETSCOPE сохраняются как имена собственные).

Список исходных названий зафиксирован в
`tests/fixtures/qwrt-r26.2.2-menu-titles.txt`. Тест не позволит добавить в
baseline название без явного отображения в теме.

## Воспроизведение на роутере

Скопировать `tools/luci-menu-audit.lua` во временный каталог роутера и выполнить:

```sh
lua /tmp/luci-menu-audit.lua
```

Скрипт только читает dispatcher tree и проверяет наличие файлов. Он не вызывает
CBI actions, не отправляет формы, не меняет UCI и не перезапускает службы.
Ненулевой код возврата означает отсутствующий CBI/template target либо
одинаковые подписи внутри одного уровня меню.

## Что проверяется в CI

- все кнопки в собственных NETSCOPE views имеют явный `type`;
- DOM ID внутри каждого собственного view уникальны;
- основные кнопки имеют обработчики в соответствующем JavaScript;
- быстрые ссылки скрывают только совпадающие URL, а `href="#"` категорий не
  считаются страницами;
- текущая вкладка NETSCOPE при повторном нажатии не перезагружается;
- зафиксированные исходные названия QWRT покрыты русским отображением.

Vendor-формы остаются ответственностью соответствующих LuCI-пакетов. Этот аудит
проверяет их маршруты и наличие view/model, но не нажимает потенциально
разрушительные кнопки сброса, прошивки, перезагрузки или удаления конфигурации.
